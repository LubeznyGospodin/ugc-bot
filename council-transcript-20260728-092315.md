# LLM Council — миграция каталога Tilda → код (2026-07-28)

## Вопрос (framed)
Мигрировать ли каталог UGC-креаторов Packman (~119 карточек на Tilda, packman-prod.ru/ugc_creators) на собственный кодовый сайт? Автоматизация Tilda ненадёжна (Store API виснет, CSV-импорт кладёт «редакциями» в чужой раздел). Данные уже в Postgres + Selectel S3 + Google Sheets; бот @ugc_radarbot (Railway) постит карточки в канал @ugc_creatory по аппруву. Владелец хочет программный контроль + self-hosting + лучше SEO. Если да — стек + что не потерять (URL/SEO/119 карточек). Если нет — как надёжно починить Tilda.

## Советники
**Контрарианец:** перестройка платформы ради разовой задачи. SEO = риск даунгрейда. Кто чинит в 3 ночи (нетех. владелец + ИИ). Узкое место — одна интеграция. Держать Tilda как ранжируемую оболочку + JSON-эмбед из Postgres, ИЛИ read-only SSG + 301.

**Первопринципщик:** две работы — покупатель (уже Telegram) и SEO (единственная причина публичной страницы). Ответ не «какой билдер», а «дешёвое, что делает 119 карточек индексируемыми + обновляемыми ботом» = не билдер. Бот пишет Postgres+S3 → генератор статики → 119 страниц, публикация = git push. Какой билдер? Никакой.

**Экспансионист:** мигрировать в платформу — программное SEO (тысячи long-tail), бренд-дашборд/маркетплейс с комиссией, POST /creators, мэтчинг, API+виджет. Next.js + Postgres + S3 + FastAPI. [Рецензенты: overreach.]

**Аутсайдер:** кто вообще заходит на сайт? «Лучше SEO от кода» — миф. 119 профилей = тонкий контент. Боль = баг интеграции. Сперва измерь трафик; если ~ноль — удалить, не перестраивать.

**Исполнитель:** мигрировать ТОЛЬКО рендер. Один FastAPI-роут в существующем Railway-сервисе, Jinja2 серверный HTML, карточки = цикл по БД, фото из Selectel. Бот флипает published=true (публикация = UPDATE). /ugc_creators/<slug> + 301 на 119 tproduct/<uid> через словарь. DNS→Railway, HTTPS free. 2–3 дня.

## Перекрёстный разбор (3 рецензента)
- Сильнейший: Исполнитель (принимает миграцию + сводит риск к нулю на своём стеке) и Аутсайдер (отказ от рамки, SEO-миф).
- Слепое пятно: Экспансионист (маркетплейс = бизнес-пивот под видом миграции, overreach).
- Все пропустили: измерить сначала (Search Console/аналитика — ранжируются/конвертят ли 119 страниц); долгосрочная поддержка нетехом; lock-in Tilda; гибрид headless-Tilda.

## Вердикт
Мигрировать СЛОЙ РЕНДЕРА (план Исполнителя), НЕ маркетплейс. Публикация = флаг в БД (UPDATE) вместо UI-автоматизации — это и есть решаемая проблема. Сперва 30-мин проверка трафика Tilda: есть органика → бережная миграция + 301 на всё; ~ноль → строить всё равно (дёшево, убивает боль Tilda), 301 старых URL, без агонии по SEO.

**Первый шаг:** Search Console по packman-prod.ru — сколько из 119 страниц в индексе и сколько органики/лидов дают.
